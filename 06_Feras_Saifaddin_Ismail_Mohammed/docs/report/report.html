1. Problem and users

AgriSoko is preparing a short demonstration for potato cooperatives, employers and innovation partners in Musanze. Visitors needed more than a running APK: they needed to know who built each part and how to verify it. AgriSoko Pocket G03 lets a person ask a natural question and receive a profile that only repeats approved facts.

Product promise

Ask by name, nickname, role, skill or feature. See confidence, the reason for the match, an evidence-based introduction, and working links to GitHub. When the network is gone, exact identity lookup still works and is labelled offline.

2. Information architecture

Tabs: Home · Ask · Team · About
Stack: Result (AI match / no-match / error) · Profile

Online flow

  1. User types a question. Empty and over-long text is rejected on the device.
  2. NetInfo reports online. Axios POST /ask with an 8-second timeout.
  3. Result shows member, confidence, reason, introduction, source badge “Live match”.
  4. Profile opens evidence URLs with Linking.

Offline flow

  1. NetInfo reports offline. The phone does not call TF-IDF.
  2. Exact name, nickname or role is compared to the bundled directory.
  3. A hit is labelled “Offline match”. A miss explains the limitation and lists names.

Recovery

Timeout and 5xx/connection errors show Retry and keep the last useful introduction on screen. Cached directory and last ask live in AsyncStorage.

5. AI design

One searchable document per member is built from name, aliases, GitHub username, role, skills, target user, problem, contribution, feature, outcome metric, tester feedback and introduction draft. Empty optional fields are skipped; the member stays in the index.

ChoiceRule
VectorizerFeatureUnion of word n-grams (1–2) and char_wb n-grams (3–5), sublinear TF, L2
SimilarityCosine
Exact boost+0.25 when a normalised name, alias, GitHub username or name token (>2 chars) is contained in the query; cap 1.0
Threshold0.45. A change must be justified by evaluation/queries.json.
GroundingintroductionDraft and evidenceLinks copied verbatim. No generative API.

Fingerprint: SHA-256 of canonical members.json, exposed as sha256:… on /model-info.

7. Testing evidence

Automated tests live in ai-api/tests/: exact name, alias, role/feature, no-match, missing question, empty dataset, API schema, 404. Run pytest -q and python build_index.py.

Evaluation queries: at least three per member (name/alias, role, feature) plus six deliberate no-match questions including weather, president, pizza, rocket, gibberish and a cooking question about potatoes that must not pick a member.

Device matrix and tester findings are recorded in TEST_LOG.pdf and FEEDBACK.pdf. At packaging time the APK was not yet installed on physical phones; those rows are completed when Feras and Lazarus run the two-device check. Two reproducible fixes should be linked to GitHub issues after device testing (planned: API URL hint on first offline launch, and suggestion chips wrapping on small screens).

Honesty rule: no farmer, cooperative statement or impact percentage is written here because none was collected.

10. Responsible AI, lessons, next steps

  • Privacy: no phones, addresses, passwords or tokens in members.json or the APK.
  • Truth: profiles refuse unverified impact. GitHub placeholder usernames must be replaced by each member.
  • AI assistance is declared in evidence/AI_USE.md. Members still own the defence of their files.
  • Lesson: a transparent TF-IDF index is easier to defend than a hidden prompt.
  • Next: deploy FastAPI to a public HTTPS URL, run EAS, film the three-minute demo, collect four consented testers.
